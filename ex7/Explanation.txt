Task 1 - La Place Mechanism
-----------------------------
Step-by-Step Solution of the Code?

To answer the first task, I wrote a small program that applies the Laplace mechanism to a simple counting query (“How many people in the dataset are older than 29?”). The idea is that we first compute the real value and then add controlled random noise to it so that the final result protects each individual’s privacy.
The script starts with a function called laplace_mech. This function takes three arguments: the true value of the query, the sensitivity of the query, and the privacy budget ε. For a counting query, the sensitivity is always 1 because adding or removing a single person can only change the count by one. The function then computes the scale parameter of the Laplace distribution by dividing the sensitivity by ε. Based on this, it draws one noise value from a Laplace distribution centered at zero and adds this noise to the true value. The idea is that the noise is large enough to mask the contribution of any one person, but still small enough that the overall statistic remains useful.
The second function, dp_count_over_29, performs the actual differential privacy-protected query. It starts by calculating the true count using the column “Age” from the dataset. After that, it calls the Laplace mechanism with sensitivity = 1 and ε = ln(2), as required in the task. The function then returns the noisy result.
At the bottom of the script, in the __main__ section, the dataset adult_with_pii.csv is loaded. The code then runs the DP counting function and prints the final noisy value. Every time you run the program, the result will look slightly different because of the added randomness, which is exactly what differential privacy relies on.
Overall, the code is fairly short, but it demonstrates the essential steps of applying the Laplace mechanism: compute the true answer, pick the correct sensitivity, add Laplace noise, and than return the perturbed value.


Explanation (a): Sensitivity of the query
Question (a):
What is the sensitivity of this query, and why?
We are looking at the query:
“Number of people in the adult dataset who are over 29.”
This is a counting query: it outputs a single integer, namely how many rows satisfy the condition age > 29.
In the standard notion of neighboring datasets for differential privacy, two datasets are neighbors if they differ in exactly one person (one row is added, removed, or changed).
If you add one person whose age is > 29, the count increases by 1.
If you add one person whose age is ≤ 29, the count stays the same.
If you remove one person whose age is > 29, the count decreases by 1.
If you remove one person whose age is ≤ 29, the count stays the same.
If you change the age of one person so they move from > 29 to ≤ 29 (or the other way round), the count again changes by at most 1.
So, in all possible cases where we move from one neighboring dataset to another, the value of the query changes by at most 1.

Δf=1

because the maximum difference in the query result between any two neighboring datasets is 1.



Task 2 - Contingency Table
--------------------------

For this task, we had to build a differentially private contingency table for any two columns of a dataset, and then apply the method to the adult data for the attributes Relationship and Race.
The idea behind the code is simple: a contingency table is basically a grid of counts. Each cell just tells us how many rows fall into a specific combination of values, like Relationship = Husband and Race = White. For a non-private table, we can simply use pandas.crosstab, which does exactly that.
To make the table differentially private, we keep the original structure but add Laplace noise to every single cell. Since each entry in the table is itself just a counting query, its sensitivity is 1 (changing one person can only increase or decrease a single cell count by one). That’s why the same Laplace mechanism from Task 1 still applies here.
In the implementation, after computing the real table, I loop through all cells and replace each value with a noised version. The noise scale is 1 / ε, following the Laplace mechanism formula. The end result is a table with the same shape and labels, but the numbers are slightly “wiggly” due to the noise. This protects individuals while keeping the overall structure of the distribution.
For the required example, I plugged in ε = 0.3 and used the columns Relationship and Race from the provided adult dataset.

Explanation (a): Does parallel composition apply for generating a contingency table? Why or why not?
Parallel composition does not apply here.
Parallel composition only works when different individuals appear in different subsets of the data. In a contingency table, every cell count is computed from the entire dataset, not from disjoint splits.
One person contributes to exactly one cell of the table, but that cell is part of the same overall dataset—so the mechanisms (one per cell) are not operating on disjoint data partitions.
Because of this, we cannot treat the cells as if they were independent parallel queries.
Instead, this is a case of sequential composition, where each cell consumes its own ε-budget if we added noise separately.
In our case, we directly assign the final ε to each cell as required by the instructions.

Explanation (b): Does the number of variables used in constructing the contingency table matter for privacy cost? Does it matter for accuracy?

Privacy cost:
Yes, the number of variables (i.e., number of cells) matters for privacy if we allocate ε separately per cell. More cells would mean more repeated applications of DP mechanisms, and by sequential composition the total privacy cost would grow. But in our implementation, the exercise explicitly asks for a total cost of ε = 0.3, so we assign that ε directly to each cell uniformly.
Thus: the number of variables doesn't increase the privacy cost in this specific implementation, but in general it would.
Accuracy:
Yes, absolutely. The more cells a contingency table has, the smaller the counts become, and the fixed Laplace noise has a larger effect relative to the true value.
A table with 2×2 cells is usually far more accurate than one with 20×20 cells, simply because the noise stays the same but the cell counts shrink.

Task 3 - Differentially private selections from sets
----------------------------------------------------
This task is about selecting the most common occupation in a differentially private way. The idea is pretty similar to Task 1: we start with a normal count, then add Laplace noise, and finally choose the highest noisy value.
The scoring function is straightforward. It simply counts how many times each occupation appears in the dataset. This number is our base “score”: the more common the job, the higher its score.
To make the selection private, we run the Laplace mechanism on each occupation’s score. Since a single person can change the count of exactly one occupation by at most 1, the sensitivity is again equal to 1. For every possible occupation, I compute its true score, add Laplace noise drawn with scale 1 / ε, and store the result. At the end, I look at all noised scores and pick the occupation that ended up with the highest noisy value.
This method is basically the Laplace-version of the exponential mechanism: we distort each score slightly and rely on the idea that the most frequent occupation is still likely to win, but without revealing the exact counts. With ε = 0.05, the noise is relatively strong, so the output may fluctuate between runs, but the privacy guarantee is strong as well.

Explanation (a):
What is the sensitivity of your scoring function?
The scoring function counts how many rows in the dataset have a specific occupation:
score(x)=∣{i:xi.Occupation=occ}∣

the count for their old occupation decreases by 1

So for any single occupation’s score, the change is at most 1.
Sensitivity = 1 (because it is a simple counting query).
This follows the standard sensitivity rule for counts from the lecture slides.

Explanation (b):
(b) What is the total privacy cost for most_common_occupation and why?
We apply the Laplace mechanism once for each occupation.
Let R be the number of unique occupations in the dataset.
For each occupation occ, we compute:
score(occ)+Laplace(1/ϵ)
score(occ)+Laplace(1/ϵ)
Because each noisy value is computed on the same dataset, these are sequential applications of differential privacy.
The lecture notes explicitly state:
applying the Laplace mechanism |R| times results in a total privacy loss of |R|·ε
Therefore:
Total privacy cost = |Occupations| × ε
This is exactly the sequential composition rule: every time we use a DP mechanism on the same data, we spend another ε of privacy.
Even though we are only returning one occupation at the end (not the noisy scores), the privacy loss happens earlier—when we generate all the noisy values. The post-processing property means returning only the argmax does not add additional privacy cost.

------------------------------------
Summation queries are a little more delicate than counting queries because a single row can contribute a very large value. To make the query differentially private, we need to make sure that the influence of any one person is bounded. The usual approach is to clip the values before summing them. Clipping means we cap the value in a fixed range, typically something like [0, B] or [-B, B], depending on the data.
Once the values are clipped, the sensitivity of the sum becomes simply the clipping bound B: if one person enters or leaves the dataset, the sum can change by at most B. With that sensitivity, we can apply the Laplace mechanism like in the earlier tasks.
In the code, I chose the clipping bound by taking the 95th percentile of the Capital Gain column. This is just one reasonable way to pick a bound without looking at exact maximums, which we are not allowed to “peek” at in a privacy-sensitive scenario. After clipping, I compute the true sum and add Laplace noise scaled by B/ε. Since the mechanism is only applied once, the total privacy cost is simply ε.
